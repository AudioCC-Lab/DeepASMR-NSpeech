# Annotation-quality audit

This directory evaluates the train/test annotation pipeline against an
**independently and manually annotated ground-truth (GT) sample**. Labels
generated by the same pipeline, copied from model output, or produced only by
another automatic model are not valid GT for this audit.

The code is public. The authors' private hand-labeled GT and any cache that can
reveal it are not included.

## What this measures

This audit answers “how often are the published SVO labels correct?” It is
separate from each annotation stage's `*run_summary.json`, which answers “how
many items completed or failed, and why?” A successful API call is not evidence
that its label is correct.

The reported fields follow the paper protocol:

- fine-grained verb: exact and alias-normalized accuracy/macro-F1;
- verb superclass: accuracy/macro-F1;
- subject and object: strict accuracy and alias/optional-LLM-resolved accuracy;
- full SVO: supplemental strict and resolved accuracy.

Open-set material descriptions are excluded because they are not normalized in
the same unified label space.

## 1. Create a blind manual-GT template

For the test audit used in the paper, the default sample size is 206:

```bash
python3 evaluation/annotation_quality/sample_human_gt.py \
  --predictions test/test_label.json \
  --split test \
  --sample-size 206 \
  --seed 2025 \
  --out private/manual_gt_test.json
```

Sampling is near-equal across recognized fine-grained verbs. The output keeps
the item/audio identifier but deliberately hides the pipeline SVO label to
reduce anchoring. Do not use `--include-context` unless the written annotation
protocol explicitly allows that context.

Each human annotator fills:

```json
{
  "gt": {
    "subject": "fingernails",
    "verb": "tapping",
    "object": "glass bottle"
  },
  "annotation": {
    "annotator_id": "annotator_a",
    "status": "complete",
    "notes": null
  }
}
```

`subject` and `verb` are required, and `verb` should be selected from the
released closed vocabulary. `object: null` is valid when there is no second
interaction object. A completed row must set `annotation.status` to `complete`
(or another non-pending status). See
[`examples/manual_gt.example.json`](examples/manual_gt.example.json).

For a defensible benchmark audit, record and retain the annotator instructions,
which evidence was available (audio/keyframe/text), whether annotators saw model
predictions, the number of annotators, and the adjudication rule.

## 2. Compare pipeline labels with manual GT

Strict and closed-vocabulary metrics require no API:

```bash
python3 evaluation/annotation_quality/evaluate_annotations.py \
  --predictions test/test_label.json \
  --ground-truth private/manual_gt_test.json \
  --out private/test_annotation_quality.json
```

The evaluator defaults to the complete, frozen v1 noun alias table at
[`data/noun_alias.v1.csv`](data/noun_alias.v1.csv). To evaluate a different
dataset or alias policy, provide another reviewed `group_id,alias` CSV:

```bash
python3 evaluation/annotation_quality/evaluate_annotations.py \
  --predictions test/test_label.json \
  --ground-truth private/manual_gt_test.json \
  --noun-aliases private/frozen_noun_alias.csv \
  --out private/test_annotation_quality.json
```

The small file [`examples/noun_alias.example.csv`](examples/noun_alias.example.csv)
only demonstrates the schema. Changing the default table changes the metric and
must be reported.

### Optional LLM adjudication

An LLM may judge noun pairs that remain unresolved after strict and alias
matching. This is a secondary, assisted score; always report the strict score
separately. Keys are read from an environment variable and never from source
files or command-line arguments:

```bash
export SILICONFLOW_API_KEY="..."

python3 evaluation/annotation_quality/evaluate_annotations.py \
  --predictions test/test_label.json \
  --ground-truth private/manual_gt_test.json \
  --use-llm \
  --llm-cache private/test_noun_judgments.json \
  --out private/test_annotation_quality.json
```

The v1 defaults freeze the released noun alias table, exact prompt,
`Qwen/Qwen3.6-35B-A3B`, temperature 0, and a 256-token output limit. The
machine-readable configuration and SHA-256 hashes are in
[`configs/paper_alias_llm_v1.json`](configs/paper_alias_llm_v1.json). A real
cache can expose GT noun pairs, so it is not published when the GT is private.
Consequently, third parties can reproduce the method on their own human GT but
cannot independently recompute the paper's exact private-GT numbers.

## 3. Optional inter-annotator agreement

If two annotators independently label an overlapping sample:

```bash
python3 evaluation/annotation_quality/inter_annotator_agreement.py \
  --annotator-a private/manual_gt_test_a.json \
  --annotator-b private/manual_gt_test_b.json \
  --out private/test_inter_annotator_agreement.json
```

The script reports agreement and Cohen's kappa for closed-set verbs/classes,
plus strict and alias-normalized pairwise agreement for open-set nouns. If only
one person annotated the sample, describe it as a manual audit and do not claim
inter-annotator agreement.

## What belongs in a benchmark paper?

The main paper does not need script-level detail. It should state enough to
judge benchmark validity: sample size and stratification, who annotated and
with what evidence, whether annotation was independent/blind, label schema,
quality/adjudication protocol, agreement or audit metrics, and limitations.
Prompts, schemas, alias rules, seeds, per-class results, and executable commands
can live in the appendix and repository.
